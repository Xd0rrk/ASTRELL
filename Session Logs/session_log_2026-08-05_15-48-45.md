# Session Log: 2026-08-05 15:48:45

## Overview
This session focused on auditing, standardizing, and optimizing the blog system for ASTRELL's portfolio. Initially, an attempt was made to migrate the entire blog architecture to pull dynamically from a Firebase (Firestore) backend, but after encountering permission issues and bugs, the system was reverted to a highly-optimized local filesystem architecture based on user requests.

## Completed Tasks and Changes Made
1. **Firebase Integration Attempt (Reverted)**
   - Created Next.js Server Actions for fetching and paginating blog posts from Firestore.
   - Refactored `app/blog/page.tsx`, `app/blog/BlogClient.tsx`, and `app/blog/[slug]/page.tsx` to support the Firebase implementation.
   - Fixed multiple reference/import bugs (`getCategories`, `latestPosts`, `email`) caused by the initial refactoring.

2. **Reverting to Local Static Architecture**
   - Disconnected the blog system completely from Firebase.
   - Restored `app/blog/page.tsx`, `app/blog/BlogClient.tsx`, and `app/blog/[slug]/page.tsx` to read exclusively from the static `lib/blog-data.ts` arrays.
   - Restored `generateStaticParams` for individual article pages.

3. **Performance and UX Optimizations**
   - **Bandwidth Optimization (Lightweight Previews)**: Modified the `BlogPage` Server Component to map over the 61 local blog posts and strip out heavy data properties (e.g., `sections`, `faq`, `keyTakeaways`). This lightweight `previewPosts` array is now passed to `BlogClient`, saving massive amounts of bandwidth and preventing the entire blog content from bundling into the client-side JavaScript.
   - **Infinite Scroll**: Implemented a native `IntersectionObserver` in `BlogClient.tsx` to automatically trigger the `loadMore` function when the user scrolls near the bottom of the active post list, providing a seamless "infinite scroll" experience without altering the existing UI design.

## Important Decisions and Reasoning
- **Abandoning Firebase (Temporary)**: Due to immediate runtime `Missing or insufficient permissions` Firebase errors, and per the user's explicit request, we bypassed the database entirely to rely on the hardcoded batches of local blog files. This ensures the app is currently stable, fully functional, and visually complete.
- **Server-Side Data Stripping**: Since `BlogClient` uses `'use client'`, directly importing the massive `BLOG_POSTS` array into it caused Next.js to ship the full text of all 61 articles to the browser on the `/blog` route. By shifting the import to `page.tsx` (Server Component) and passing a mapped "preview" array as a prop, we drastically optimized page load times.
- **Native IntersectionObserver**: Used the native browser `IntersectionObserver` API for the infinite scroll rather than introducing a new third-party dependency, keeping the footprint small and localized.

## Issues Encountered and Resolutions
- **Firebase Permission Error**: The database threw "insufficient permissions" when fetching data. 
  - *Resolution*: Reverted to the local static arrays (`BLOG_POSTS`) to maintain progress on the UI/UX front.
- **Undeclared/Duplicate Variables (`getCategories`, `latestPosts`, `email`)**: During the Firebase refactor, several variables were accidentally overwritten or duplicated.
  - *Resolution*: Audited the file, removed duplicate imports, and restored the missing state variables (`email`, `subscribed`) and mapped constants (`displayedPosts`).
- **Client Bundle Bloat**: Sending 61 full blog objects to the client.
  - *Resolution*: Mapped the objects on the server to omit the `sections` property.

## Remaining Tasks & Recommendations for Future Work
- **Firebase Re-Integration**: When ready, the Firestore database security rules need to be updated to allow public read access (or the correct Admin SDK needs to be configured). Once the database is accessible, the blog should be re-connected to it.
- **True Server-Side Pagination**: Currently, the system loads all 61 lightweight previews into memory on the client and slices them for pagination. While perfectly optimized for 61 posts, if the blog scales to hundreds of posts, true server-side cursor pagination should be re-implemented.
- **UI Design Tweaks**: The user noted that the design is "beautiful" and requested no changes, so UI work on the blog list is considered complete unless new instructions are given.
