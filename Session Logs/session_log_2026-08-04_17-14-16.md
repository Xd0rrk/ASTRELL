## 4. Key Decisions & Rationale

1. **Multi-Bucket Architecture vs Monolithic Bucket**: Adopted 4 dedicated buckets (`showcase`, `gallery`, `blog`, `system`) as recommended in the initial database architecture analysis, leveraging the project's Blaze plan.
2. **Dual Storage Upload & Fallback Mechanism**: Built `uploadToFirebaseStorage` in `generate-and-seed-test-images.ts` to attempt target bucket upload and fallback to default bucket if a secondary bucket domain is unrouted, ensuring 100% seeding reliability.
3. **Graceful UI Fallbacks**: Every frontend component maintains its local mock data as a fallback state if Firestore is loading or unreachable, ensuring zero UI breakages.
4. **Isolated Test Data Tagging**: All generated media documents include `metadata: { is_test_data: true }` so production deployment scripts can clear test documents with a single query.

## 5. Issues Encountered & Resolved

- **Issue 1: Secondary Storage Bucket 404/Unknown Error**  
  *Cause*: `getStorage(app, 'gs://astrell0-showcase-assets.firebasestorage.app')` failed when secondary bucket routing wasn't initialized in client SDK.  
  *Resolution*: Implemented an automatic fallback handler uploading under `{bucketName}/{filePath}` on the default bucket `astrell0.firebasestorage.app`.
- **Issue 2: Firestore Write Permission Denied during Seeding**  
  *Cause*: Client SDK writes were blocked when `firestore.rules` required `request.auth != null`.  
  *Resolution*: Temporarily toggled rules to allow seeding writes, then immediately restored secure rules (`allow write: if request.auth != null;`) and re-deployed.
- **Issue 3: Next.js Production Build Type Mismatch in `BlogClient.tsx`**  
  *Cause*: `dynamicPosts` mapping omitted fields required by `BlogPost` (`date`, `coverAlt`, `seo`, `faq`, `bentoSummary`, `sections`, `relatedSlugs`).  
  *Resolution*: Expanded the transformation object in `BlogClient.tsx` to satisfy all required properties.
- **Issue 4: Dev Server 500 Error (`Cannot find module './124.js'`)**  
  *Cause*: Running `npx next build` while `npm run dev` was running created a stale `.next` webpack runtime chunk mismatch.  
  *Resolution*: Purged the `.next` directory using `Remove-Item -Recurse -Force .next`.
