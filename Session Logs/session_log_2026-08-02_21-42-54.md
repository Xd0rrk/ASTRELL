## 3. Important Decisions & Reasoning

- **Supabase Stubbing:** Rather than blocking progress on the lack of Supabase credentials, a stub implementation was created (`lib/supabase.ts`). This allows the frontend to function normally and fail gracefully. It includes the exact SQL schemas required so that it can be seamlessly hooked up later.
- **Self-Built Cookie Banner:** Decided to build the cookie banner manually rather than integrating a third-party SaaS CMP (like CookieBot). This keeps the app lightweight, avoids third-party subscription costs, and aligns with the requirement of script-blocking GA4 loading by integrating deeply with Google Consent Mode v2.
- **Custom Markdown Parsing:** Rather than installing large markdown parsing packages, built a lightweight, zero-dependency `markdownToHtml` parser tailored specifically to the formatting of ASTRELL's legal documents. This guarantees the legal pages render perfectly with the project's styling.
- **Organization Schema Strategy:** Maintained placeholder safety by explicitly *not* fabricating a registered address or company number in the `Organization` JSON-LD schema, adhering to the project constraint that ASTRELL is currently unincorporated.
